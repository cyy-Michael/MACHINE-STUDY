机器学习算法实验与可视化平台项目实施方案

一、项目定位

本项目不是单纯建立一个数据库，而是开发一个机器学习实验与可视化平台。

用户可以在网页中完成以下操作：

1. 选择已有数据集。
2. 查看数据集基本信息。
3. 选择机器学习算法。
4. 调整算法参数。
5. 启动模型训练。
6. 查看训练进度。
7. 查看预测结果和性能指标。
8. 对比不同算法的实验结果。
9. 查看图表、混淆矩阵、预测曲线或聚类效果。

最终需要提交：

1. 一份 PDF 实验报告。
2. 一个可以访问的 GitHub 或 GitLab 代码仓库。
3. 一个可以运行的 Python 后端。
4. 一个可以运行的 Vue 前端。
5. 项目架构说明和运行说明。

注意：按照课程要求，邮件中只提交一个 PDF 附件。代码上传到 GitHub 或 GitLab，数据集本体不要提交到代码仓库。


二、项目总体目标

（一）最低完成目标

1. 支持分类和回归两类机器学习任务。
2. 使用 2 到 3 个已有数据集。
3. 完成 4 到 6 个机器学习算法。
4. 至少 3 到 4 个算法由小组自己实现。
5. 至少实现数据加载、预处理、训练、预测和评估流程。
6. 前端可以选择数据集、算法和参数。
7. 后端可以完成训练并返回结果。
8. 前端可以展示指标和图表。
9. 代码可以在另一台电脑上按照 README 运行。
10. 完成实验报告和项目演示。

（二）推荐完成目标

1. 支持分类、回归和聚类三类任务。
2. 完成 6 到 8 个算法。
3. 至少一半算法自己实现。
4. 同时提供自实现算法和 Scikit-learn 算法作为对照。
5. 支持参数调整。
6. 支持多次实验结果对比。
7. 支持训练时间、预测时间和模型效果对比。
8. 对至少一个算法进行改进或调参。
9. 前端重点展示数据和实验结果，而不是只做页面美化。


三、推荐技术方案

1. 编程语言：Python、JavaScript 或 TypeScript。
2. 后端框架：FastAPI 或 Flask。
3. 前端框架：Vue 3。
4. 前端组件库：Element Plus。
5. 图表库：ECharts。
6. 前后端通信：WebSocket；普通数据请求也可以使用 HTTP 接口。
7. 机器学习参考库：Scikit-learn。
8. 版本管理：Git。
9. 代码托管：GitHub 或 GitLab。
10. 开发工具：Visual Studio Code。

推荐架构如下：

Vue 前端
    |
    | HTTP / WebSocket
    |
Python 后端
    |
    +-- 数据集加载模块
    +-- 数据预处理模块
    +-- 算法注册模块
    +-- 模型训练模块
    +-- 模型预测模块
    +-- 指标评估模块
    +-- 实验记录模块
    |
本地数据集和实验结果

如果现有数据是 CSV、Excel 或图片文件，不要一开始设计复杂数据库。先完成统一的数据读取模块和数据集管理模块。只有在需要保存大量实验记录时，才使用 SQLite 保存实验元数据和结果。


四、建议的算法组合

（一）分类算法

1. K 近邻算法 KNN。
2. 逻辑回归 Logistic Regression。
3. 决策树 Decision Tree。
4. 朴素贝叶斯 Naive Bayes。
5. 支持向量机 SVM。

（二）回归算法

1. 线性回归 Linear Regression。
2. 岭回归 Ridge Regression。
3. 决策树回归 Decision Tree Regressor。

（三）聚类算法

1. K-Means。
2. 层次聚类作为可选扩展。

（四）建议的实现策略

第一优先级：

1. KNN。
2. 线性回归。
3. 逻辑回归。
4. 决策树或 K-Means。

第二优先级：

1. 朴素贝叶斯。
2. 岭回归。
3. SVM。

不要所有算法都只调用 Scikit-learn。可以使用 Scikit-learn 作为基准实现，但应将部分核心算法手动实现，从而提高“自实现模型比例”。


五、数据集处理方案

（一）第一步：整理数据集清单

为每个数据集建立一份说明，至少包含：

1. 数据集名称。
2. 文件格式。
3. 样本数量。
4. 特征数量。
5. 每一列的含义。
6. 标签列名称。
7. 标签类型。
8. 是否存在缺失值。
9. 是否存在类别不平衡。
10. 适合的算法类型。

建议建立如下表格：

数据集名称 | 样本数 | 特征数 | 任务类型 | 标签列 | 缺失值 | 推荐算法

（二）第二步：确定任务类型

1. 标签是有限类别，例如 0、1 或多种类别，通常属于分类问题。
2. 标签是连续数值，例如价格、温度或评分，通常属于回归问题。
3. 没有标签，只希望发现数据分组，通常属于聚类问题。

（三）第三步：统一预处理

1. 处理缺失值。
2. 处理重复数据。
3. 删除无意义的编号列。
4. 将字符串类别转换为数值。
5. 对需要标准化的模型进行特征标准化。
6. 将数据划分为训练集和测试集。
7. 固定随机种子，保证实验可以复现。
8. 防止测试集信息泄露到训练集。

建议默认使用：

训练集：80%
测试集：20%
随机种子：42

如果需要验证集，可以使用训练集中的交叉验证，不要反复使用测试集调参。


六、统一机器学习流程

所有算法都应按照相同流程运行：

1. 选择数据集。
2. 读取数据。
3. 检查字段和数据类型。
4. 清理缺失值和异常值。
5. 构造特征矩阵 X 和标签 y。
6. 划分训练集和测试集。
7. 进行必要的标准化或编码。
8. 初始化算法和参数。
9. 调用 fit 进行训练。
10. 调用 predict 进行预测。
11. 计算评价指标。
12. 记录训练时间和预测时间。
13. 保存实验参数和实验结果。
14. 将结果返回前端。

自实现算法建议使用统一接口：

class Model:
    def fit(X, y):
        pass

    def predict(X):
        pass

这样可以让后端用同一种方式调用不同算法，也方便以后继续增加模型。


七、评价指标设计

（一）分类任务

必须至少展示：

1. Accuracy，准确率。
2. Precision，精确率。
3. Recall，召回率。
4. F1-score。
5. 混淆矩阵。

可选展示：

1. ROC 曲线。
2. AUC。
3. 每一类的识别结果。
4. 训练时间和预测时间。

（二）回归任务

必须至少展示：

1. MAE。
2. MSE。
3. RMSE。
4. R²。

可选展示：

1. 真实值与预测值散点图。
2. 残差图。
3. 训练时间和预测时间。

（三）聚类任务

建议展示：

1. 聚类标签。
2. 二维散点图。
3. 轮廓系数。
4. Calinski-Harabasz 指数。
5. 不同聚类数量下的效果对比。

九、后端接口建议

接口一：获取数据集列表

GET /api/datasets

返回内容：

1. 数据集名称。
2. 任务类型。
3. 样本数。
4. 特征数。
5. 标签列。

接口二：获取数据集详情

GET /api/datasets/{dataset_name}

返回内容：

1. 字段列表。
2. 字段类型。
3. 数据样例。
4. 缺失值统计。
5. 标签分布。

接口三：获取算法列表

GET /api/algorithms?task_type=classification

返回内容：

1. 算法名称。
2. 算法类型。
3. 是否为自实现算法。
4. 默认参数。
5. 可调参数。

接口四：启动实验

POST /api/experiments

请求内容：

1. 数据集名称。
2. 算法名称。
3. 任务类型。
4. 算法参数。
5. 测试集比例。
6. 随机种子。

接口五：查询实验结果

GET /api/experiments/{experiment_id}

返回内容：

1. 实验状态。
2. 训练结果。
3. 预测结果。
4. 评价指标。
5. 训练时间。
6. 可视化数据。

接口六：WebSocket 训练通信

WS /ws/experiments/{experiment_id}

主要用于：

1. 返回训练进度。
2. 返回实时日志。
3. 返回训练异常。
4. 通知前端训练完成。

十二、14 天实施进度

第 1 天：明确需求和建立仓库

目标：项目可以开始协作。

任务：

1. 全体成员阅读教案要求。
2. 确定项目名称和组名。
3. 确定五人分工。
4. 创建 GitHub 或 GitLab 仓库。
5. 建立项目目录。
6. 制定分支名称和提交规范。
7. 确定开发环境。

验收标准：

1. 每个人都可以拉取和提交代码。
2. README 初步建立。
3. 五人分工已经写入文档。

第 2 天：分析数据集

目标：知道每个数据集能做什么。

任务：

1. 统计文件和字段。
2. 检查样本数量和缺失值。
3. 确定标签列。
4. 判断任务类型。
5. 选择最终使用的数据集。
6. 编写数据字典。

验收标准：

1. 至少确定 2 个数据集。
2. 每个数据集都有字段说明。
3. 已确定分类、回归或聚类任务。

第 3 天：完成数据加载和预处理

目标：后端可以统一读取数据。

任务：

1. 编写数据加载函数。
2. 编写缺失值处理函数。
3. 编写类别编码函数。
4. 编写标准化函数。
5. 编写训练集和测试集划分函数。

验收标准：

1. 至少两个数据集可以成功加载。
2. 预处理后可以输出 X 和 y。

第 4 天：完成第一个自实现算法

十七、常见失分风险

1. 所有算法都只调用 Scikit-learn，没有自实现内容。

5. 测试集信息泄露到训练过程。

9. 报告中的截图和代码不是同一版本。
10. 五个人的分工写得不清楚。
11. 只注重页面美观，没有解释算法原理。
12. 最后一天才进行前后端联调。
13. 邮件附件不符合“只允许一个 PDF”的要求。

十九、现在立即执行的任务

第一天请五个人完成以下事项：

1. 把现有数据集文件整理到一个目录。
2. 统计每个数据集的样本数、字段数和标签列。
3. 确定最终使用的 2 到 3 个数据集。
4. 确定分类、回归和聚类中实际要做的任务。
5. 从推荐算法中选择 4 到 6 个。
6. 确定哪些算法自己实现，哪些算法使用 Scikit-learn 对照。
7. 建立 GitHub 或 GitLab 仓库。
8. 创建上述项目目录。
9. 每个人安装 Python、Node.js、VSCode 和 Git。
10. 让所有成员在本地成功运行一个最简单的数据读取示例。

第一阶段不要追求功能很多，最重要的是先完成一条完整链路：

数据集加载 -> 数据预处理 -> 模型训练 -> 模型预测 -> 指标计算 -> 前端展示。

只要这条链路跑通，后续增加算法和图表就属于扩展工作。
